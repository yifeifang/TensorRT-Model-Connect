# Component license and source distribution audit

Reviewed: 2026-09-11. Scope: the seven Windows showcase capabilities, their native bridges, the installed build/reference environments, and the proposed source example. Model checkpoints have a separate [model audit](MODEL_LICENSE_AUDIT.md). This records engineering release decisions supported by the listed terms; it is not a blanket clearance for every possible binary build or commercial deployment.

The approved boundary for this change is **source distribution with user-installed dependencies**. The source export tool uses an explicit file allowlist, records content hashes, rejects unapproved binary inputs and recognizable credentials, and excludes development output. No third-party SDK, interpreter, browser runtime, model weight, compiled engine, compiler, font file or prebuilt native DLL is conveyed by that source export. Installing a component locally remains subject to its own terms. A container image would convey the files in its layers and would require its own inventory and redistribution review.

## What this PR can and cannot publish

The reviewable source example may include project-authored JavaScript/HTML/CSS, C++ bridges, family-specific source patches, CMake/PowerShell/Python build instructions, tests, legal records and the approved photograph. `source-files.json` is the explicit list. `source-release.cjs` exports to a new destination without overwriting existing files and writes `SOURCE_MANIFEST.json` with exact sizes and hashes. Text is normalized to LF before hashing, matching the repository's `.gitattributes`; the approved photograph remains byte-identical. It also rejects Windows user/machine paths in release source; historical logs, research and qualification receipts are excluded instead of presenting them as portable build evidence.

The resulting PR does not distribute an executable release or prebuilt Docker image. SDKs, models, optional media and build dependencies must be acquired directly by the user, preserving publisher terms and access requirements. A script must not bypass a license gate or silently claim acceptance for the user. Local generation/install avoids our redistributing those bytes; it does not waive restrictions on the user's use or subsequent publication. Before offering a binary app or populated container, separately review a version-pinned bill of materials, exact file redistribution grants, required notices/source obligations, and model/media terms for that artifact.
